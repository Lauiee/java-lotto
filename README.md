# java-lotto-precourse

# 요구사항(플로우 흐름으로 정리)
- - -
## 로또 구입
- [x] 로또 구입 금액 입력
- [x] 로또 구입 금액 1,000원 단위 검증
## 로또 생성
- [x] 로또 구입 금액에 따라 발행 로또 개수 결정
- [x] 로또 구매 개수 출력
- [x] 발행 로또 개수에 맞게 로또 발행
  - [x] 발행되는 로또는 6개의 숫자를 가진다
  - [x] 발행되는 로또의 숫자는 중복을 허용하지 않는다
  - [x] 발행되는 로또의 범위는 1~45로 제한된다
  - [x] 발행된 로또의 숫자는 오름차순으로 정렬된다
- [x] 발행 된 로또를 전부 출력
## 당첨 번호 입력
- [x] 당첨 번호 입력
- [x] 당첨 번호 구분자 검증
- [x] 당첨 번호 개수 검증
- [x] 당첨 번호 숫자가 맞는지 검증
- [x] 당첨 번호 숫자 범위 검증
- [x] 당첨 번호 숫자 중복 검증
## 보너스 번호 입력
- [x] 보너스 번호 입력
- [x] 보너스 번호 숫자가 맞는지 검증
- [x] 보너스 번호 숫자 범위 검증
- [x] 보너스 번호 당첨 번호와 중복 검증
## 결과
- [x] 각 로또별로 당첨 번호 + 보너스 번호와 일치하는 숫자의 개수에 따라 당첨 판단
- [x] 당첨 케이스 별로 출력
- [x] 당첨된 금액 합산
- [x] 로또 구입 금액 대비 당첨금을 비교해 수익률 계산
- [x] 계산된 수익률 출력

# 구현 순서
### 1. 메인 플로우부터 빠르게 구현(테스트 코드 같이 작성)
### 2. 구현된 코드 분리
### 3. 확장성 여부 판단 및 특정 패턴 도입 여부 결정
### 4. 리팩토링

# 신경 쓸 부분
### - 최대한 객체지향 적인 코드를 지향
### - 또한 클린코드 역시 지향
### - 코드의 가독성을 신경쓰면서 작성
### - 패턴을 도입한다면 도입하는 근거를 확실히
### - 람다와 스트림 적극 활용

# 리팩토링
### 1. 테스트 -> Parameterized Test로 업그레이드
### 2. 5개 당첨 + 보너스 번호 당첨 케이스 리팩토링
### 3. 세부 메서드 리팩토링
